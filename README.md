# WheelPilot 轻窗

> 仿 Flyme 小窗的角落轮盘启动器 —— 为被厂商拦截 `startActivity` 的机型准备的替代通道。

一个仿 Flyme 小窗形态、用 Kotlin + Jetpack Compose 写的悬浮轮盘启动器：在屏幕左右下角向上滑动，
弹出环形应用轮盘，松手即启动。启动通道不依赖普通 `startActivity`，而是优先走特权 shell（`am start`），
用来绕开荣耀 iAware 一类对后台应用启动的拦截。

## 特性

- **角落热区**：左/右下角感应区，上滑呼出，把手轻点也可；宽高、边缘内缩、离底高度都可调，横屏、游戏、锁屏息屏时自动撤下；键盘弹出时热区整体让出触摸（打字时删除、大写键照常可点）。
- **环形轮盘**：6 或 8 个槽位，半径 / 图标 / 张角可调，弹簧式入场，图标底座按原图标轮廓自适应圆角；从角落滑出后可一路滑到图标上松手启动。
- **更多面板**：应用与工具双页签、左右滑页、拼音首字母分组、最近使用、固定位、4 列网格。
- **快捷工具**：截屏、锁屏、手电筒、识屏、微信/支付宝/云闪付扫码付款、打开剪贴板里的链接等，可放进轮盘。
- **三种启动通道**：特权服务（ADB/Root 配对）→ Shizuku → 普通 Intent，逐级降级。
- **前台黑名单**：指定应用在前台时不呼出轮盘（需「使用情况访问」权限才生效）。
- **轻量打开**：通知中心、通知横幅、控制中心、应用跳转（含登录授权与应用分享）等场景下，应用以浮窗打开而不是全屏；生效范围默认限定在轮盘里的应用，避免误转支付与游戏。
- **小窗分层**：连续打开多个小窗时自动错开（默认 24 dp），超过台数上限（默认 3 台）把最早的一个转后台；横竖屏各记各的几何；可设「点小窗外面时其余缩小」；「更多」面板提供小窗全屏 / 小窗缩小 / 收起小窗三个批量动作。
- **配置备份**：槽位、外观、行为参数导出成一个文本文件，换机或调乱后一键恢复；日志可整份导出。
- **新拟态 UI**：全套自绘控件（凹槽轨道、浮起按钮、真实滑块），无 Material 默认观感。
- **包体约 3.9 MB**：R8 + 资源收缩 + ABI 过滤（arm64-v8a / armeabi-v7a）。

### 3.20.1 修复（11-19 真机日志定位）

四条缺陷都在「判定环节」，不在启动环节：

- **常驻通道永久失效**：`tryShellStart` 的闸门用 `available()`（此刻手里有没有活 binder），而它本身不触发绑定。`warmUp` 只在 App 启动时试一次，那一刻 Shizuku 若未就绪（后启动、重启过、后授权），通道此后永不启用 —— 真机日志里全程没有一行 `shell-start`。现改为 `possible()` + 后台补绑（`kickBind`）：本次走老路、下次即命中，且不在启动关键路径上等 6 秒绑定。
- **确认窗口 0.42 秒太短**：任务表轮询原为「6 次 × 70ms」，冷启动刚发出 `startActivity` 就到点，必然落成 `task-not-found`。改为递增退避 9 次（上限约 2.5 秒），首轮立即查一次，热启动不受影响。
- **`am stack list` 已随 Android 12 移除**：`preflightResizeable` 与轮询兜底都还在用它，等于没有兜底。统一改走 `dumpsys activity activities`。
- **oneStep 冷启误判**：验证窗口原为 300/500 毫秒两轮，酷安在 800 毫秒时 task 尚未建出就判失败，随即又发一次 `startActivity`，两个启动请求互相打架。改为 350/700/1100 三轮，且只有「task 不存在」才继续等，形态是全屏则立即回落。

### 3.20.0 新增（系统增强）

这些能力移植自同类工具「时光」4.2 的逆向分析，全部在「设置 → 系统维护 → 小窗与增强」里开关。

- **常驻 shell 通道**：Shizuku UserService 常驻进程内直调 `IActivityTaskManager`，取代每次 `app_process` 冷启 JVM；`app_process` 保留为兜底。转窗耗时从「数百毫秒」降到一次 binder 往返。
- **源头小窗**：以 shell 身份 `startActivityAsUser` + `windowingMode/launchBounds` 直接启动，消除「先全屏铺开、再缩成窗」的跳变。
- **重聚焦**：转窗后补一次 `setFocusedTask(-1) → setFocusedTask(task)`，已在后台的任务不再被重置回入口页。
- **尺寸标定**：部分 ROM 会把请求的小窗再打折（MagicOS 实测 74%→60%），按品牌给默认补偿系数并可在设置页标定。
- **残留清理**：启动前移除同包「不可见」的浮窗残留（要求该应用还有可见窗口，绝不碰后台栈）。
- **后台启动放行**：`ActivityOptions` 显式声明 `MODE_BACKGROUND_ACTIVITY_START_ALLOWED`（Android 14+）。
- **分享面板接收**：注册透明 Activity，「小窗打开」出现在系统分享列表里，收到内容即用小窗启动 —— 分享会话不再经过「先全屏再转窗」，微信不会清掉已选好友。
- **分屏兜底**：freeform 被 ROM 全拒时，退一级用相邻启动推入分屏。
- **实况通知**：小窗运行状态做成常驻通知，同时写四条通道（Flyme 胶囊 extras / HyperOS `miui.focus.*` / Android 16 `requestPromotedOngoing` / 普通 ongoing），认哪条用哪条；可选用 shell 身份补投一次绕过厂商白名单。
- **通知面板**：任意界面拉出全屏通知列表（按应用分组、点卡片回会话、单条滑掉、可切「归档」页），API 31+ 真模糊背景。
- **亮屏统计 / 弹幕 / 通知存档**：锁屏亮屏时统计未读条数（解锁 5 秒后撤）；横屏微信/QQ 消息飘屏；通知标题正文按行归档到本机文件（上限 200 条，可一键清空）。
- **侧边栏**：屏幕边缘 5 dp 感应条，往里滑拉出应用列表 + 字母索引（复用「更多」面板的拼音分组）。
- **竖列快捷菜单**：轮盘之外的第二套排布，从角落里向上排图标，与轮盘共用同一份条目。
- **智能音量**：接管音量键按档位给非均匀步进（2/4/6/10%）并自绘音量条。
- **触摸锁**：整屏拦截触摸防误触，长按顶部胶囊解锁，息屏自动解除。

## 工作原理

```
PilotService（无障碍服务）
   ├── CornerHotspot   角落悬浮窗，监听上滑手势
   ├── WheelOverlay    轮盘绘制 / 命中测试 / 点击启动
   └── AppSheetActivity 更多面板（应用 + 工具）
          │
          └── AppLauncher
                 ├── shell 通道：priv-kit / Shizuku → am start -n <pkg>/<activity>
                 ├── intent 通道：startActivity（可能被厂商拦截）
                 └── 小窗降级：windowingMode 100（厂商）→ 5（AOSP freeform）→ 全屏
```

悬浮界面走 `TYPE_ACCESSIBILITY_OVERLAY`，因此不需要 `SYSTEM_ALERT_WINDOW`。

无障碍配置里 `canRetrieveWindowContent=true` + `flagRetrieveInteractiveWindows`。这一项是必须的：
判断「屏幕上有没有输入法窗口」只能读 `getWindows()` 里的窗口类型（`TYPE_INPUT_METHOD`），
该列表在内容权限关闭时拿不到，会让键盘让位、轻量打开的输入法过滤、失焦判定全部静默失效。
**只读窗口类型与前台包名，不采集、不保存任何界面文本**，也不联网。

## 构建

```bash
# 1. 配好 SDK 路径
echo "sdk.dir=/path/to/android-sdk" > local.properties

# 2. 编译
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`（未签名）。

需要签名时在 `local.properties` 追加（该文件已被 `.gitignore` 排除）：

```properties
WHEEL_KEYSTORE_FILE=pilot-release.jks
WHEEL_KEYSTORE_PASSWORD=你的密码
WHEEL_KEY_ALIAS=pilot
```

没有填这几项也能正常构建，只是输出未签名 APK。

> 注意：`compileSdk` 需要 37，因为 priv-kit 0.21.0 的 AAR 声明了这个下限。
> 若你的 SDK 版本更低，可尝试降 priv-kit 版本再对齐 `compileSdk`。

## 使用

1. 安装 APK，打开「轻窗」。
2. 点「去开启」启用无障碍服务（部分系统会提示"受限设置"，需在应用信息里允许）。
3. 勾选最多 8 个应用放上轮盘（应用页顶部还可勾选快捷工具）。
4. 「特权服务」→ 配对：系统设置里打开*无线调试 → 使用配对码配对设备*，把六位码填进输入框（配对期间别关系统窗口）→ 启动服务。
5. 回桌面，从左下角或右下角向上滑动呼出轮盘。

跳过第 4 步也能用，但启动会退回普通 Intent，在拦截机型上可能失效。

诊断日志：

```bash
adb logcat -s WheelPilot:D
```

`launch <应用> -> shell-ok` 表示走通特权通道；`intent-ok` 表示已降级。

## 权限说明

| 权限 | 用途 |
|---|---|
| `BIND_ACCESSIBILITY_SERVICE` | 绘制悬浮界面与注入手势 |
| `QUERY_ALL_PACKAGES` | 配置页列出本机应用 |
| `INTERNET` / `ACCESS_NETWORK_STATE` | 无线调试配对走本地网络 |
| `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC` | 特权服务常驻 |
| `POST_NOTIFICATIONS` | 配对码回填通知 |
| `BIND_NOTIFICATION_LISTENER_SERVICE` | 可选，识别通知（微信消息入口、轻量打开的通知两档场景） |

**本项目不联网上报任何数据**，无统计、无账号、无广告。

## 已知限制

- 轮盘 6–8 个槽位；热区固定在左右下角，只能调宽高、内缩与离底高度，不能拖到屏幕其它位置。
- 前台黑名单依赖「使用情况访问」权限，未授予时识别不到当前应用，黑名单不生效。
- 部分厂商 ROM 会杀掉无障碍服务，需要手动加白名单 / 关电池优化。
- 特权服务依赖无线调试，重启手机后需重新启动服务。
- 小窗分层依赖特权通道的 `am task` 命令：没有特权时只能错开启动位置，不能改已开窗口的几何。
  部分 ROM 没有 `am task move-to-back`，此时「超限驱逐」与「收起小窗」退化为仅记日志，不会销毁窗口。
- 键盘在屏期间热区不接收触摸（设置 → 场景暂停 可关）。这是有意的：热区层级高于输入法，
  拦截后即使注入手势也送不到键盘，只能从源头不拦。

### 轻量打开的限制（重要）

- **是「事后转窗」不是「拦截」**：通知点击、控制中心磁贴、跨应用跳转、分享目标都由发起方直接投递
  Intent/PendingIntent，第三方没有 hook 点。目标应用会先以全屏出现约 200–400 ms，再被转成浮窗。
- **登录授权、应用分享与应用跳转在系统层面不可区分**，三者共用一条判据：打开其中任意一个，
  另外两个会一起打开，界面上三行始终同进同退。
- **从轮盘、快捷工具、「更多」面板点图标启动的应用不会被转窗**：这些入口在发起启动时会打一个时间戳，
  保护期内（4 秒，同一个包放宽到 8 秒以覆盖冷启动慢的应用）一律按"用户自己点的"处理。
  否则轮盘是悬浮窗、不在前台栈里，无障碍看到的变化与"在 A 里点开了 B"完全同形，必然误转。
- **分享、登录授权只做「改几何」，不重投 Intent**：系统里没有把已存在的全屏 task 就地变成浮窗的公开命令，
  能用的只有 `am task resize`（不动栈）和重新 `am start --windowingMode 5`（会重投 Intent）。
  分享与授权靠 `resultTo` 链回传结果，重投一次流程就断了 —— 所以这两类场景只用 resize，
  resize 不成宁可直接保持全屏。这也意味着**分享面板被点开时不会再被误转成浮窗**（面板本身在排除表里）。
  - 冷启动时不会再被升级成「重投」（旧版会，结果是把微信首页拉起来、把「选择聊天」堆成全屏）。
    现在改为等目标 task 自己出现后再改几何，最多等 2.5 秒；等不到就保持全屏。
  - **一次分享只处理一次**：识别出分享/授权后对目标包加 45 秒流程锁，期间的窗口变化一律不转窗。
    「选联系人 → 聊天页 → 发送」在慢机器上会连开三四个 Activity，解锁的话会出现
    「全屏选联系人 + 浮窗聊天页」两个窗口叠加、输入框被压、内容发不出去（3.11.1 录屏中的现象）。
  - **同包有多个 task 时不转窗**：微信分享时「选择聊天」和「聊天页」可能分属两个 task，
    只 resize 其中一个正是双层窗口的成因，此时宁可整个流程保持全屏。
  - 分享/授权用一套更高的浮窗几何（88% 宽 × 80% 高，上下各留 10%），
    避免聊天页顶部消息和底部输入框被切掉。普通场景仍用原生小窗几何。
- **应用跳转默认也走保守方式**：跳转与授权/分享在系统层面同形，无法区分。默认只 resize，
  失败就保持全屏；设置 → 轻量打开 →「跳转也强制转窗」可以放开，代价是可能中断分享与授权。
- **通知的判定不再强制「通知栏展开过」**：锁屏点通知、点横幅、从桌面直接点都不经过通知栏，
  旧判据因此全部漏判。现在只要「该应用的通知在 12 秒内到达」且前台变成了它就算。
- **「只对轮盘里的应用生效」不限制通知/横幅/控制中心**：这三类用户在系统界面里点的就是某个应用的通知，
  再拿轮盘名单卡它只会让功能看起来是坏的（典型：微信不在轮盘里，点通知仍是全屏）。
- **已在前台跑着的全屏应用，转窗成功率天然低**：跨窗口模式的 `am task resize` 多数 ROM 不支持，
  而 `am start` 对已存在的 task 不会改模式。执行器为此加了「转后台再以浮窗拉起」的兜底，
  但微信这类单实例应用可能回到首页。通知/跳转的冷启动（task 不存在）一定以浮窗打开；
  分享/授权冷启动则按上面的规则等 task 出现后只改几何，改不了就全屏 —— 保证分享能用优先。
- **输入法窗口不参与判定**：键盘是与宿主无关的独立窗口，弹出时会报一条包名为输入法的窗口事件，
  与「应用内跳转」在事件流里同形。现在按三层拦：启用输入法包名表 → 包名/类名特征 → 屏幕上的
  输入法窗口类型；键盘在屏期间一律不转窗。宁可少转一次，也不能把键盘转成浮窗导致无法打字。
- **复制链接不做成自动**：Android 10 起非前台应用读剪贴板返回 null。本项改为在「更多」面板提供
  「打开链接」工具 —— 点击时应用在前台，能正常读到内容并用浮窗打开。
- 应用跳转需要特权通道（或 Shizuku）才能可靠转窗；无特权时退回 ActivityOptions 通道，成功率下降。
- 判断条件依赖通知栏/控制中心的窗口类名，不同 ROM 类名不同，可能需要按机型增补。
